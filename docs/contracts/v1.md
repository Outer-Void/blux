# Contract v1 reference

The canonical schemas are in `contracts/v1/*.schema.json` (JSON Schema 2020-12, `$id` = `urn:blux:contract:v1:<kind>`).
Shared definitions are in `common.schema.json`.

| Kind | `contract` | Purpose |
|---|---|---|
| capability | `blux.capability` | What can be invoked, with I/O schemas, side effects and permissions (ADR-0003) |
| capability-set | `blux.capability-set` | A list of capabilities (`.blux/capabilities.yaml`, `registry/`) |
| execution | `blux.execution` | Request to run one capability (ADR-0004) |
| result | `blux.result` | Outcome: succeeded / failed / rejected |
| receipt | `blux.receipt` | Audit record: lineage, policy decision, hashes. Persisted by blux-system, not BLUX |
| artifact | `blux.artifact` | Content-addressed output descriptor |
| model | `blux.model` | Model descriptor. Invoked only through capabilities |
| project | `blux.project` | `.blux/manifest.yaml` |
| policy | `blux.policy` | Default-deny authorization rules (ADR-0007) |
| error | `blux.error` | Normalized error (ADR-0006) |

## Validation layers (in order)
1. Parse: strict JSON/YAML (`MALFORMED_INPUT`)
2. `contract` matches the expected kind (`INVALID_ENVELOPE`)
3. `contract_version` syntax (`MALFORMED_CONTRACT_VERSION`) and support (`UNSUPPORTED_CONTRACT_VERSION`)
4. JSON Schema (`SCHEMA_VALIDATION_FAILED`)
5. Semantic checks the schema cannot express (`SCHEMA_VALIDATION_FAILED`):
   - real calendar timestamps, and `finished_at ≥ started_at`;
   - `model_id` prefixed by its `provider`;
   - unique capability and rule ids;
   - embedded `input_schema`/`output_schema` are themselves valid JSON Schemas.

## Fixtures
`tests/fixtures/v1/valid/<kind>/` are frozen 1.0 documents and must stay valid forever.
`tests/fixtures/v1/invalid/<kind>/` are `{"expect": CODE, "document": ...}` negative cases.
