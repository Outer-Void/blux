# BLUX Model API v1

Schemas: `contracts/model-api/v1/` (`urn:blux:model-api:v1:*`). SDK: `blux_sdk.model_api`. Runtime:
`blux_runtime.models`. Decision record: [ADR-0010](../adr/0010-model-api.md).

## Logical models

| model | for |
|---|---|
| `blux-main` | general-purpose default |
| `blux-fast` | low latency and cost |
| `blux-reason` | multi-step reasoning and planning |
| `blux-code` | code generation, review and repair |

`blux models` prints the catalog: each model with the capabilities its routes can provide.

## Request (`blux.model-request`)

```json
{"contract": "blux.model-request", "model_api_version": "1.0", "model": "blux-main",
 "system": "You are terse.",
 "context": [{"kind": "document", "title": "README", "content": "..."}],
 "messages": [{"role": "user", "content": "Summarize the README."}],
 "tools": [{"name": "lookup", "description": "...", "input_schema": {"type": "object"}}],
 "tool_choice": "auto",
 "response_format": {"type": "json_schema", "name": "summary", "schema": {"type": "object"}},
 "capabilities": ["tools"],
 "generation": {"max_output_tokens": 800, "temperature": 0.2, "top_p": 1, "stop": ["END"], "seed": 7},
 "deterministic": false, "stream": false, "timeout_ms": 60000,
 "routing": {"allow_fallback": true, "providers": ["openai", "anthropic"], "exclude_providers": []},
 "client": {"name": "my-app", "version": "1.2.0"}}
```

**Messages.**
- Roles are `user`, `assistant` and `tool`.
- An assistant message may carry `tool_calls` (`{id, name, arguments}`).
- A `tool` message answers one with `tool_call_id`.
- The last message is from the user or a tool.

**Capabilities.** These are hard requirements for the serving route: `streaming`, `tools`,
`structured_output`, `deterministic`, `long_context` and `local_only`. `stream`, `tools` (unless
`tool_choice: none`) and `response_format: json_schema` imply their capability.

## Response (`blux.model-response`)

| field | |
|---|---|
| `status`, `finish_reason` | `completed`/`incomplete`/`tool_calls`; `stop`/`length`/`tool_calls`/`content_filter`/`other` |
| `output` | `text`, `json` (parsed and schema-checked when `response_format` asked for it), `tool_calls` (validated against the tools' schemas, never executed) |
| `usage` | input, output, total, reasoning and cached-input tokens; `null` where the provider reports none; `reported_by_provider` |
| `provider` | backend, provider, provider model, route, locality, the provider's request id |
| `routing` | serving route, every attempt (`succeeded`/`failed`/`skipped` with error code, reason, latency, retries), `fallback_used`, `degraded`, notes |
| `determinism` | requested, supported by the route, applied temperature and seed |
| `timing` | total latency, time to first token |
| `linkage` | the BLUX operation (when called through `model.generate`) |

## Streaming (`blux.model-stream-event`)

The event types are `start`, `route` (one per attempt), `delta` (text), `tool_call`, `usage`, then `end`
(with the full response) or `error`.

- Event numbering (`seq`) is continuous across routes.
- After a `route` event, the deltas of any earlier attempt are void.

In-process, pass `on_event` to `ModelRouter.generate` or `Runtime.execute`. From the CLI, use
`blux generate ... --events FILE`.

## Errors (`blux.model-error`)

| code | retryable | fallback |
|---|---|---|
| INVALID_REQUEST, UNKNOWN_MODEL, CAPABILITY_UNAVAILABLE | no | no |
| PROVIDER_NOT_CONFIGURED, PROVIDER_AUTH_FAILED, PROVIDER_QUOTA_EXCEEDED (billing/quota) | no | yes |
| PROVIDER_RATE_LIMITED, PROVIDER_UNAVAILABLE, PROVIDER_ERROR, PROVIDER_TIMEOUT | yes | yes |
| PROVIDER_REJECTED | no | no |
| CONTEXT_TOO_LONG | no | yes |
| CONTENT_FILTERED | no | **no**: never routed around |
| STRUCTURED_OUTPUT_INVALID, TOOL_CALL_INVALID, BACKEND_PROTOCOL_ERROR | yes | yes |
| ALL_ROUTES_FAILED, TIMEOUT | yes | no |
| CANCELLED, INTERNAL_ERROR | no | no |

Every error carries `attempts`. Messages are scrubbed of credential-shaped strings.

## Routing table (`blux.model-routes`)

```json
{"contract": "blux.model-routes", "model_api_version": "1.0", "routes_id": "my-routes",
 "backends": {"bluxgpt": {"kind": "subprocess", "entrypoint": "bluxgpt blux-model-backend"}},
 "models": {"blux-main": {"routes": [
   {"route_id": "main.openai", "backend": "bluxgpt", "provider": "openai", "provider_model": "gpt-5-mini",
    "locality": "remote", "tier": "primary", "capabilities": ["streaming", "tools", "structured_output"],
    "determinism": {"temperature": false, "seed": false}, "credential_env": ["OPENAI_API_KEY"]}]}, "...": {}},
 "defaults": {"max_attempts": 3, "allow_fallback": true, "timeout_ms": 120000}}
```

**Where the table comes from.**
- **Default.** The packaged default (`blux_runtime/models/default_routes.json`) routes to BluxGPT providers.
- **Override.** `--routes FILE` or `$BLUX_MODEL_ROUTES` replaces it.
- **Local models.** A route can point at a local OpenAI-compatible server, such as llama.cpp's
  `llama-server`, with `provider: openai-compatible`, `base_url` and `locality: local`.

## Backend protocol

**Input.** stdin is one object:

```json
{"model_api_version": "1.0", "request": {"...": "..."}, "route": {"...": "..."},
 "context": {"operation_id": "...", "deadline_ms": 60000}}
```

**Output.** stdout is stream events, one per line, ending with `end` or `error`; exit 0. Anything else is
`BACKEND_PROTOCOL_ERROR`.

The route excludes `credential_env`. The variables it names are passed in the backend's environment.

## CLI

```bash
blux models
blux generate blux-main "Say hi"
blux generate blux-code "Write a haiku about diffs" --events -   # stream events on stderr
blux generate blux-fast --request req.json --system-store ./truth --receipt-out receipt.json
```

The default policy for `generate` (`blux_runtime/models/model_policy.json`) allows `model.generate` for
users, services and agents with the `net:model` grant. `--policy` replaces it.
